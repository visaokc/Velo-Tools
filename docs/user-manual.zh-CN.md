# Velo Tools 教程手册

适用版本 **1.7.1**。按插件里的五个区域找功能，一次学会一件事。案例使用虚构的物体，不要求你拥有某个特定角色或工程。

**第一次使用？** 先看[安装与第一个工程](#game-start)，再看[五个工作阶段](#game-files)。已经在制作？直接选择你要找的按钮所在的 Tab。

[顶点组工具](#vertex-groups) · [网格工具](#mesh) · [权重工具](#weights) · [材质工具](#materials) · [游戏](#game)

英文 UI 目前把网格工具写作 **Grid tool**，权重工具写作 **Weight Tool**，就是这里对应的两个 Tab。Blender 简体和繁体中文界面都使用插件的简体中文词表。本手册会区分按钮原名和通俗解释。

## 顶点组工具

把顶点组理解成一张“哪些点跟着哪根骨头动”的名单：组名用来找骨骼，权重表示跟随的强弱。改组名不等于重新分配权重。本 Tab 主要整理名字；要搬动权重数值，请去权重工具。

### 顶点组操作

<a id="vg-merge"></a>
#### 合并重复名字的顶点组

把小数点前名字相同的组收拢起来，例如 **7**、**7.001**、**7.003**。适合合并物体后留下的重复组，不会自动判断两个完全不同名字的骨骼是否含义相同。

**位置：** 顶点组工具 → 顶点组操作 → 合并顶点组。

##### 操作步骤
1. 先另存工程。在物体模式中，只选需要整理的网格。
2. 打开物体数据属性里的顶点组列表，确认带点号的组确实属于同一根骨骼。
3. 点击合并顶点组，查看合并后的基础组，并转动对应骨骼检查。

##### 小案例
你把两段袖子合并了，一段使用 **7**，另一段使用 **7.001**。合并顶点组后，两段的权重归到 **7**，同一根骨骼就能找到它们。不要拿它合并 **Arm.L** 和 **Arm.R**：这里的点号是左右侧名字的一部分，并不是多余后缀。

##### 检查与排错
重复后缀组应当消失，原来的影响归入基础名字。重叠部分的权重仍需检查，不要默认它已经规格化。若误合并了有意义的点号名称，立即撤销。需要人为指定名字对应关系时，应使用[映射表](#vg-general)。

<a id="vg-gaps"></a>
#### 补齐缺号并排序

补出缺少的空编号组，并按数字顺序排列。有些导出格式会把组在列表中的位置当成骨骼编号，因此空组有时是必要占位，而不是垃圾。

**位置：** 顶点组操作 → 补齐顶点组。

##### 操作步骤
1. 在物体模式中选择目标网格，确认它使用数字组名。
2. 点击补齐顶点组。
3. 查看列表顺序，再抽查几个顶点原有的组归属。

##### 小案例
原来只有 **0、4、2**，执行后变为 **0、1、2、3、4**。新增的 **1** 和 **3** 是空的；工具没有凭空补出缺失的手臂或腿部权重。

##### 检查与排错
原有权重仍应属于原来的组。若这些占位是导出所需，就不要紧接着又点“删除未使用顶点组”。补齐也不是把部件独立编号换成统一编号；那需要正确的[骨架模式](#game-wwmi-skeleton)。

<a id="vg-unused"></a>
#### 删除未使用的顶点组

删除所选网格上没有正权重的组，让列表更清爽。它不是“删除很小的权重”，也不是“限制每个点最多受几根骨骼影响”。

**位置：** 顶点组操作 → 删除未使用顶点组。

##### 操作步骤
1. 保存工程，只选择要清理列表的网格。
2. 先确认当前导入/导出方式是否需要空编号占位。
3. 执行清理，检查列表，并测试原本能动的一处关节。

##### 小案例
靴子从整个人体继承了两百个组名，但实际只有脚踝和脚掌的组有权重。清理后列表变短，靴子不会因此自动改跟另一根骨骼。

##### 检查与排错
原先丢失的权重不会被恢复。如果后续导出需要完整编号列表，可有意识地使用[补齐缺号](#vg-gaps)。不要把本操作与会改变数值的[规格化选中顶点](#weight-normalize)混为一谈。

<a id="vg-remove-all"></a>
#### 删除全部顶点组，重新制作权重

彻底清空所选网格的顶点组。只有在你决定舍弃现有权重时才使用，不要把它当成通用的导出修复按钮。

**位置：** 顶点组操作 → 删除全部顶点组。

##### 操作步骤
1. 另存一份工程，确认没有选中作为参考的原始身体。
2. 对替换网格执行删除全部顶点组。
3. 重新创建或传递需要的权重，再尝试摆姿势和导出。

##### 小案例
新导入的配饰带着另一套骨架的无关组。只清空这个配饰，再从正确的参考模型传入头部或手部权重。

##### 检查与排错
列表会变空；即使骨架修改器还在，物体也可能不再跟骨骼变形。按钮不删除骨架本身。若连参考模型的权重也删了，请撤销或打开之前保存的副本。

### MMD 映射

<a id="vg-mmd-setup"></a>
#### 建立 MMD 到游戏的名字对照表

你要建立的是类似 **UpperArm.L → 23** 的字典。左列是 MMD/源顶点组名，右列是工程需要的游戏身份。写下一行对照，并不会传递权重数值。

**位置：** 顶点组工具 → MMD ↔ 统一编号映射。

##### 操作步骤
1. 在游戏 Tab 选择正确游戏，并设置其导出组件集合。
2. MMD 源物体选带有名字的参考网格，目标组件选游戏导入网格。让两者在同一空间对齐。
3. 只有需要重命名源骨骼时，才填写 MMD 骨架。
4. 创建或选择映射表文本块，点击“从源物体补行”。加减号负责单行增删；清空映射表清的是字典，不是网格权重。

##### 小案例
你的袖子使用 **UpperArm.L**，原始 Component 使用 **23**。把相应网格填入两个对象框，再补行、匹配。得到一条经检查的对照才是成果，不代表其余行已经全部正确。

##### 检查与排错
“MMD 源物体”不是导出白名单：当前 MMD 表会按组名作用于导出集合内所有符合条件的网格。对象框变红表示保存的精确名字暂时找不到。可以点 X 清空，或让同名网格重新出现；相近名称不会被擅自替代。

<a id="vg-mmd-match"></a>
#### 按位置匹配，然后检查对照

匹配器比较每个组的“权重重心”，也就是这组影响主要集中在哪里。位置接近只能提示可能对应，不能证明两根骨骼功能一样。

**位置：** MMD ↔ 统一编号映射 → 匹配位置 → 按位置匹配→写入本表。

##### 操作步骤
1. 两个模型未变形时形状接近，先用静置位置。
2. 只有当前可见姿势更适合比较时才改用姿态位置，此时两侧的骨架、ShapeKey 和修改器变形都会参与比较。
3. 点击匹配，检查右列，特别留意手指、面部、多层衣物和左右对称部位。
4. 打开可视化校对，对不确定的行手动修正。再次点匹配才会改表；只改变姿势不会重写已保存的对照。

##### 小案例
源模型手臂下垂，目标模型手臂抬起。先让可见姿势接近，再选姿态位置进行匹配。若左手腕连到了右手腕，应修正那行，而不是一味放大距离阈值。

##### 检查与排错
匹配不应用修改器，也不改网格。无权重组和特殊辅助组可能不会被补入。这种制作时的位置匹配，与生成[原始骨骼名文件](#vg-wwmi-map)时逐顶点验证完整权重的算法不是同一回事。

<a id="vg-mmd-rename"></a>
#### 四个改名按钮分别该什么时候用

四个按钮操作两边不同的网格。“源”和“目标”指上方对象框，不是当前视图里随便选中的物体。

**位置：** MMD ↔ 统一编号映射 → 两行改名/恢复按钮。

##### 操作步骤
1. 先检查并保存映射表。
2. 按下表选择操作哪一侧、改往哪种名字。
3. 检查顶点组；填写了骨架时也检查源骨骼。测试变形后再覆盖唯一工程。

| 操作 | 实际含义 |
| --- | --- |
| 源物体改为统一编号 | 把 MMD 源组改成右列身份；可同步修改填写的源骨骼名 |
| 源物体恢复 MMD 名 | 恢复源快照，包括原来的组名、顺序和权重 |
| 目标物体改为 MMD 名 | 让目标 Component 使用源侧名字，并按映射表排列 |
| 目标物体改为统一编号 | 让目标组回到游戏身份，保持当前组顺序 |

##### 小案例
想在导入的数字 Component 上用可读名字刷权重，就选“目标物体改为 MMD 名”。不要点源物体按钮，否则改的是你的参考。

##### 检查与排错
源物体恢复不是纯粹反向改名，它也可能恢复之前的权重。不要指望快照之后刷的新权重在恢复操作后仍然保留。导出预处理本来就使用临时副本，并非每次导出前都要永久改名。

<a id="vg-table-save"></a>
#### 保存、读取和复用映射表

把检查过的对照保存在 blend 内，或单独导出文本。表里保存的是名字对应关系，不包含网格、贴图或整套骨架备份。

**位置：** MMD 或通用映射 → 映射表、内置文本同步、导入/导出映射文本。

##### 操作步骤
1. 在面板顶部创建或选中需要的文本块。
2. 修改行后，点击“写入内置文本”的箭头，再保存 blend。
3. 若在 Blender 文本编辑器里修改了表，点击“从内置文本读取”的箭头，让面板重新读取。
4. 导出映射文本可另存文件；复用时用导入映射文本。覆盖之前先看清当前选的是哪份表。

##### 小案例
把 **Sleeve mapping** 存进工程。第二个工程可以读取导出的文本，但仍要核对目标编号是否来自同一对象源、同一种骨架模式。

##### 检查与排错
MMD 表与通用表的选择器、工作对象相互独立。空行、重复或冲突的行需要检查。成功读入旧表不代表它适用于新 dump。清空或替换有价值的表之前，先导出备份。

### 通用映射与可视化校对

<a id="vg-general"></a>
#### 在任意两套网格之间对照组名

通用顶点组映射不要求 MMD 命名，也不要求游戏数字组，适合普通骨架之间的名字整理。

**位置：** 顶点组工具 → 通用顶点组映射。

##### 操作步骤
1. 填写本面板的源物体、目标物体和可选骨架，不是上方 MMD 面板的字段。
2. 选择静置或姿态位置，从源补行，然后按位置匹配。
3. 知道模型尺度下合适距离时，再启用最大距离限制。被拒绝的行应检查，不应接受任意远处匹配。
4. 根据目标执行“源改目标名”“恢复源”“目标改源名”或“目标改目标名”，然后保存表。

##### 小案例
源手套使用 **finger_index_01**，目标骨架使用 **Index1.L**。对齐手套和目标手，检查该行后改名。手套原来刷的值仍是原值，不会自动采样目标手的权重。

##### 检查与排错
填写骨架是为同步改名；姿态比较真正读取的是各网格的变形结果。通用表不能直接当成当前 MMD 导出表。多个关节集中在一起时，请按骨骼含义补行，并[检查连线](#vg-review)。

<a id="vg-review"></a>
#### 用重心连线与未匹配列表校对

可视化校对把源、目标组的重心连起来，便于在改名之前发现左右交叉和距离很远的误配。

**位置：** MMD 或通用映射下的可视化校对面板；通用映射另有未匹配列表。

##### 操作步骤
1. 先完成一轮映射，再开启该面板的叠加显示。
2. 打开标签和未匹配目标点。画面太乱时调整连线显示距离。
3. 绕模型观察，至少从两个角度检查手腕、肩、手指和中线。
4. 修正表格，再检查一次；需要重新匹配时才点匹配按钮。结束后关闭叠加。

##### 小案例
左袖子的线穿过躯干连到右臂，回到那行核对名字并换成左侧身份。短连线也不一定正确，因为重叠的衣服层可能有相同重心。

##### 检查与排错
MMD 和通用叠加会避免互相重叠。姿态位置模式下，摆姿势会更新连线，但不更新保存的行。出现空名字或未匹配项时，应检查对象与表格，不是去规格化权重。

<a id="vg-pick"></a>
#### 点击叠加点看权重，拖动叠加点改映射

可视化点可以交互。点击用于查看一组权重，拖动用于改对应关系，两者不是同一操作。

**位置：** MMD 或通用映射 → 开启可视化叠加 → 3D 视图。

##### 操作步骤
1. 选好源/目标网格后，打开对应叠加。
2. 点击组端点，进入该网格/组的权重绘制模式查看影响。
3. 把来源端点拖到正确目标端点，写入对应行。
4. 检查表格，结束后关闭叠加或离开权重查看会话。

##### 小案例
袖子来源点连到了错误手臂，把它拖到正确目标，再看更新后的行。已被使用的目标点拖到另一目标，会把其对应来源一起重指，因此要检查所有受影响行。

##### 检查与排错
来源拖到空白会清空它的目标，不是取消拖动；已有目标拖到空白则保持不变。查看时拾取器暂用零强度减去笔刷，会话结束恢复保存的笔刷状态。真正准备绘制前先检查笔刷，不要误以为点一下已经搬动权重。

### WWMI 原始骨骼名

<a id="vg-wwmi-map"></a>
#### 生成并保存 WWMI 原始骨骼名

把难读的 WWMI 数字组整理成有证据的原始骨骼名对照。需要对应的解包模型，工具不能只看一个数字就猜出骨骼名字。

**位置：** 顶点组工具 → WWMI 数字编号 ↔ 原始骨骼名；游戏选择鸣潮。

##### 操作步骤
1. 解包路径指向对应的 .uemodel 资产，对象源目录指向 WWMI 提取结果。
2. 首次保留相似度和体素大小默认值，点击生成映射表。
3. 检查结果。1.7.1 会逐顶点比较完整权重，并拒绝无法唯一确认的骨骼身份，不只是判断网格远不远。
4. 点击保存匹配结果到源目录，把 **WWMI_MatchingResult.json** 与对象源一起保存。“从源目录读取”可以恢复已保存的结果。

##### 小案例
身体与袖子有几根骨骼影响同一批点，但强弱不同。完整权重能区分仅看中心位置可能弄反的骨骼。结果保存后，即使解包目录不在了，也能复用其中的名字和骨架快照。

##### 检查与排错
旧 v1 结果要从正确解包资产重新生成 v2。调低相似度不能证明一根有歧义的骨骼是谁。不要用别的 Component 或角色的几行数据强行填掉错误。

<a id="vg-wwmi-bind"></a>
#### 切换数字名字，或为 WWMI 网格绑定骨架

用已保存的对照，让工程更方便摆姿势。名字切换作用于所选网格；一键绑骨会处理配置好的整个 WWMI 组件集合，范围更大。

**位置：** WWMI 数字编号 ↔ 原始骨骼名。

##### 操作步骤
1. 按上一篇生成或读取有效映射。
2. 只想局部检查时，选中一个网格，使用“切换至原始名字”或“切换至数字编号”。
3. 只需要骨架时点导入骨架。镜像骨架要与网格导入方向一致。
4. 要处理整个 Mod 集合时点一键绑骨。.L/.R 后缀转换是可选项，只处理支持的、能确认的成对名称。

##### 小案例
先把一段导入袖子切换为原始名字，确认手臂组正确，再给整个 Mod 集合绑骨。轻轻转动上臂，检查袖子是否跟随。

##### 检查与排错
手动添加一行并不等于建立了已验证身份。被使用的映射有歧义时操作会停止。提取结果、映射与骨架快照应一起保存。不要只看到名字变了，就认为编号模式一定适合当前导出。

### 雕刻与材质整理

<a id="mesh-sculpt"></a>
#### 把多个物体临时合起来雕刻，再传回原物体

先生成一个临时合并物体，让笔刷可以跨过原本分离的接缝。雕刻完成后，原物体仍是接收修改的位置。

**位置：** 网格工具 → 多物体雕刻。

##### 操作步骤
1. 另存工程，在物体模式选中原始网格，点击创建合并物体。
2. 在临时物体上用移动现有顶点的笔刷雕刻。期间不要重构网格、开启 Dyntopo、删点，也不要改变原物体的拓扑。
3. 普通网格使用“应用合并物体雕刻”，把位置传回原物体。
4. 原物体有 ShapeKey 时用带 Shape Keys 的应用按钮，它还会把这次位置差加到各个形态键上。

##### 小案例
一件上衣由躯干和两条袖子组成。临时合起来修顺肩部接缝。没有形态键时普通应用；有呼吸键时使用 ShapeKey 版应用，然后测试呼吸是否仍正常。

##### 检查与排错
分别查看每个原物体，并把重要形态键切到 0 和 1 检查。该流程依赖顶点对应，新增顶点不会因为“看着很近”就自动找到原位置。改坏拓扑时撤销或打开副本。

<a id="mesh-prefix"></a>
#### 给替换网格添加 Component 身份

以 **Component N** 开头的名字告诉导出器，这个网格属于哪一个提取部件。数字来自对象源，不是随便起的文件夹编号。

**位置：** 网格工具 → 材质工具 → 给选中物体添加 Component 前缀。

##### 操作步骤
1. 从导入参考和对应对象源里确认目标 Component。
2. 选中替换网格，填写按钮旁的编号。
3. 点击添加，检查最终物体名，并把物体放在导出集合中。

##### 小案例
只有确认参考袖子属于 Component 2，才对 **Sleeve** 使用数字 **2**。这会给袖子正确的部件身份，但不会让不兼容的骨骼权重自动变得可用。

##### 检查与排错
不要照抄示例编号。开启导出时自动按材质拆分后，材质前缀也可能参与归属；关闭后则按整个物体自身的 Component 名分配。详见[导出范围](#game-scope)。

<a id="mesh-material-name"></a>
#### 生成同名材质，同时保留原有贴图接线

让处理后的材质跟随物体名称，方便材质拆分识别 Component，也让工程更好找。

**位置：** 网格工具 → 材质工具 → 选中物体生成材质球。

##### 操作步骤
1. 在物体模式选中需要整理的网格。
2. 查看第一个实际生效的材质槽，确认它正是你要保留接线的材质。
3. 执行生成，检查物体、网格、材质的名字，再看贴图显示是否保持。

##### 小案例
物体叫 **Component 2 Sleeve**，材质却叫 **Material.018**。执行后，当前编辑材质获得有意义的对应名字，同时保留漫反射和原图映射。

##### 检查与排错
当前编辑材质优先保留原名，旧材质可能变成 **Backup …**。其他使用者的内容与槽位不被删除。DATA 和 OBJECT 材质槽都支持，不用先手动换关联方式。后续不同材质槽和面归属会保留，这不是把所有材质压成一个的按钮。

<a id="mesh-auto-name"></a>
#### 物体改名时自动同步材质名

生成材质按钮旁的小刷新图标负责监听之后的改名。默认关闭，设置保存在场景中。

**位置：** 网格工具 → 材质工具 → 生成材质球旁的图标开关。

##### 操作步骤
1. 先设置当前游戏的导出组件集合。
2. 打开图标开关，开启时使用 Blender 的高亮状态。
3. 给集合或子集合内一个已有网格改名。
4. 检查网格和材质是否跟随新名字。

##### 小案例
把单材质物体 **Component 2 Sleeve** 改成 **Component 2 LongSleeve**，名字会同步。刚复制出来的新物体会先登记而不立即修改，之后发生改名才触发同步。

##### 检查与排错
自动处理只针对零或一个材质槽的网格，多材质物体会跳过。导出集合外也不监听。旧工程已有的不一致想立即修复，请使用[手动生成同名材质](#mesh-material-name)。

<a id="mesh-split"></a>
#### 按材质分离，并决定微小 ShapeKey 是否保留

根据面使用的材质，把一个网格拆成多个物体。旁边的阈值决定：某个形态键在拆出的部分几乎不动时，要不要保留。

**位置：** 网格工具 → 材质工具 → 按材质分离；ShapeKey 清理阈值。

##### 操作步骤
1. 另存工程，检查各面的材质分配。分离按实际槽位归属，不按肉眼颜色判断。
2. 设置阈值。默认 **0.0001**，按网格局部坐标距离判断；要保留细微动作就用更小的值。
3. 选中网格，执行按材质分离。
4. 查看拆出的物体与保留的形态键。流程在进入编辑模式前选中 Basis，拆完仍停在 Basis。

##### 小案例
上衣里有袖子和纽扣两种材质。一个只抬袖子的键，在纽扣部分的所有位移低于阈值，就可能从纽扣物体删除。若纽扣确实要轻微移动，应把阈值设得比该动作更小。

##### 检查与排错
这个阈值可能删除某个分块上近似空的键，不会修复已经串到一起的变形。阈值过大会吞掉真实细节，必要时撤销重设。先选 Basis 是为了避免后续合并时，用错误的活动形态填补缺失键。

<a id="mesh-merge"></a>
#### 把使用同一套图片的物体合并

按材质使用的图片集合，把选中网格分组后合并，减少零散物体。它不是贴图打包，也不等于合并材质槽。

**位置：** 网格工具 → 材质工具 → 按贴图合并。

##### 操作步骤
1. 在物体模式选择至少两个要处理的网格。
2. 检查材质用到的全部图片，不只看漫反射。
3. 执行合并，检查最终物体、材质槽和 ShapeKey。

##### 小案例
三段布料使用相同的漫反射和法线，金属扣使用另一张图。布料组可以合在一起，扣子保持独立；材质槽仍然保留，不会被压成一个着色器。

##### 检查与排错
没有图片的网格会跳过，避免把所有无贴图物体混在一起。漫反射相同但其他图片不同，不一定算同一套。合并后再次检查 Component 名和真实集合归属。

<a id="mesh-contamination"></a>
#### 保守清理重复串入的 ShapeKey 变形

尝试清除完整材质区域上“完全相同、重复串入其他键”的位移。这是针对特定模式的修复，不是万能形态键修复器。

**位置：** 网格工具 → 材质工具 → 清理 ShapeKey 污染。

##### 操作步骤
1. 另存副本，在物体模式选中有问题的网格。
2. 检查多个形态键里疑似重复的动作。
3. 执行清理，阅读保护源、修复和跳过数量。
4. 逐个测试受影响的键。若原本就是有意组合，撤销。

##### 小案例
独立的 **SleeveLift** 是正确的，但相同的整块袖子位移又原样出现在几个各自有其他动作的键里。工具能在至少三个键的证据中认出受保护源和纯重复区域时，才把其他键里多出来的那部分还原为 Basis。

##### 检查与排错
不同或叠加后的变形不会被近似相减；有歧义就跳过，不删除任何键，也不用旁边的阈值。共享、只读、不合适的键关系或过大的快照可能被跳过。有意重复的相同动作也可能看起来像污染，因此修复数量不等于错误已被证明。

### 网格实用工具

<a id="mesh-fill"></a>
#### 补齐基础网格数据

为缺少数据的网格添加 **COLOR** 和 **TEXCOORD.xy**。空 UV 只是占位，不是自动完成的展开。

**位置：** 网格工具 → 材质工具 → 实用工具 → 补齐缺失网格数据。

##### 操作步骤
1. 选中新建网格，查看物体数据属性。
2. 执行补齐缺失网格数据。
3. 确认 UV 和颜色层存在，再按需求展开和制作。

##### 小案例
新建腰带没有 UV，也没有颜色层。操作会创建空主 UV 和黑色 COLOR，但仍需要手动展开腰带，漫反射才能正确显示。

##### 检查与排错
它不会恢复原模型特有的打包数据、法线或骨骼权重。先看目标 Component 的实际格式，不要假定补两层就满足所有需求。只有格式明确需要时，才用对应平滑法线生成器。

<a id="mesh-modifiers"></a>
#### 对有 ShapeKey 的网格应用指定修改器

当 Blender 普通“应用”因存在形态键而拒绝时，用这个工具处理选定修改器。各个形态键仍然必须得到兼容的几何结果。

**位置：** 网格工具 → 实用工具 → 对带 ShapeKey 的物体应用修改器。

##### 操作步骤
1. 另存副本，让目标网格成为活动物体。
2. 打开对话框，只勾选本次需要应用的修改器。
3. 除非有意烘焙姿势，否则保留“不包含骨架变形”。
4. 应用后检查修改器列表，并测试重要形态键。

##### 小案例
对称衣服已有几种贴合体型的键，现在需要应用 Mirror。只选 Mirror，再比较 Basis 和各个贴合键的两侧结果。

##### 检查与排错
不是所有改变拓扑的修改器组合都能保持形态键一致。若键带驱动或关键帧，对话框会提示这些动画数据会丢失，要保留工程备份。报错或形态损坏都不算成功烘焙，使用撤销或副本恢复。

<a id="mesh-linear"></a>
#### 把顶点颜色存储转换为 Linear

把 COLOR/COLOR1 转为工具链需要的存储方式。这是数据格式处理，不是“把模型换个颜色”。

**位置：** 网格工具 → 实用工具 → 顶点颜色转 Linear。

##### 操作步骤
1. 保存工程，选中相关网格。
2. 分清哪些颜色层来自提取，哪些是后来手绘。
3. 只有流程需要 Linear 存储时才执行转换。
4. 检查颜色层，先导出一份对照，再推广到更多物体。

##### 小案例
旧工程网格使用较早的颜色存储。只选择它的副本，不选择原始参考，转换后在同一游戏光照下比较两者的颜色行为。

##### 检查与排错
它不会生成缺失的描边法线，也不能判断某游戏各通道的含义。打包数据在 Blender 中看起来怪，不代表可以随意重涂。确认目标着色器结果之前保留原版。

### UV 与描边法线数据

<a id="mesh-octahedral"></a>
#### 把平滑法线写入 TEXCOORD1

给遵循该约定的着色器存储平滑方向。可以把它理解成额外的着色说明，而不是移动贴图的 UV 岛。

**位置：** 网格工具 → UV 工具 → 平滑法线-八面体 UV。

##### 操作步骤
1. 确认目标着色器和导出格式需要这种数据。
2. 所选网格必须已有第一层 UV，它决定方向的参照。
3. 备份原有 **TEXCOORD1.xy**，再执行生成。
4. 导出并检查描边，尤其是接缝。

##### 小案例
新建低模配饰在兼容流程中描边有棱角。先在副本生成平滑方向，对比生成前后的外轮廓，并检查原本贴图方向是否保持。

##### 检查与排错
操作会创建或覆盖 TEXCOORD1.xy，不是适用于所有游戏的描边修复。改变主 UV 方向会改变编码结果。终末地源格式若使用其他存储位置，应看下面对应工具。

<a id="mesh-texcoord4"></a>
#### 为终末地生成 TEXCOORD4 平滑法线

部分终末地 Component 把平滑法线 X/Y 存在 **TEXCOORD4.xy**。本工具用于给新几何制作这种表示。

**位置：** 网格工具 → UV 工具 → 生成平滑法线 TEXCOORD4。

##### 操作步骤
1. 检查提取部件的 .fmt 和保留的参考图层。
2. 原模型的辅助数据尽量保留；在新网格上准备主 **TEXCOORD.xy**。
3. 先给新网格生成，再把它合入 Component。
4. 导出后在游戏检查轮廓。

##### 小案例
新袖口要并入使用 TEXCOORD4 描边法线的终末地部件。先生成袖口自己的图层，旧袖子原有的数据保持不动。

##### 检查与排错
完全同位置的重复点会共同计算平滑，不需要合并 UV 岛。已有 TEXCOORD4 会被覆盖。它不能逐字节复原删掉的原资产烘焙结果，不要为了新增一小块就重算整个原模型。

<a id="mesh-color-normal"></a>
#### 生成 COLOR 描边法线，并明确启用

仅用于确定把兼容平滑法线存入 COLOR 的终末地部件。COLOR 只是存储容器，不是所有部件都用它做同一件事。

**位置：** 网格工具 → 顶点色工具 → 生成平滑法线 COLOR；启用 COLOR 描边法线。

##### 操作步骤
1. 像上一篇一样，先核对格式和参考数据。
2. 选择新几何生成 COLOR；生成后会自动勾选启用。
3. 已经制作好的兼容 COLOR，可以只勾选，不重新计算。
4. 完整导出以重建 mod.ini，再检查描边。

##### 小案例
新袖口使用兼容 COLOR 格式，先生成，再手绘微调。如果手绘后又点生成，颜色数据会被覆盖。

##### 检查与排错
导入 COLOR 默认由游戏原生控制。不勾选不会阻止普通 COLOR 导出，也不会关闭游戏已经打开的选择器。同 Component 中一块导出网格选择启用，可能让兼容自定义 draw 共用该启用范围；不兼容格式和受保护路径仍走原生。它不是描边粗细滑条，也不是通用透明遮罩。

### 集合分配

<a id="mesh-route-preview"></a>
#### 在集合树中规划材质分块的位置

先预览材质拆出的部分要去哪，再真正拆分。树中的集合是真实 Blender 集合；材质叶子是计划中的分组，不一定已经是一个物体。

**位置：** 网格工具 → 按材质分离所属集合。

##### 操作步骤
1. 设置当前游戏的导出组件集合。
2. 点击刷新材质分组。
3. 用加号建子集合，选中一个材质叶子。
4. 点击目标集合的导入/分配图标，把计划分组放过去。小三角只负责展开收起，不负责分配。

##### 小案例
合并衣服里有布料和饰边，建立 **Cloth**、**Trim** 两个子集合，再把虚拟叶子分到对应位置。

##### 检查与排错
移除子集合会把计划分组收回父集合，不是要求删除网格。已经拆开的物体跟随真实集合，包括在 Outliner 手动移动后的归属。不要相信很久没刷新的预览。这些操作可能自动关闭“忽略嵌套集合”，以免新子集合无法导出。

<a id="mesh-route-apply"></a>
#### 按规划拆入集合，或再按贴图聚合

把预览落实为真实物体。按材质操作保留材质分块；按贴图操作还会尝试把图片集合相同的部分合并成更少物体。

**位置：** 按材质分离所属集合 → 两个分离按钮。

##### 操作步骤
1. 完成[集合规划](#mesh-route-preview)，另存副本。
2. 需要独立材质分块时，使用按材质分离到集合。
3. 想减少兼容物体数量时，选择带贴图聚合的操作。
4. 在 Outliner 查看真正生成的物体，检查名字、材质、ShapeKey。

##### 小案例
想单独编辑袖口和袖子，就按材质保留分块。几个饰边使用完全相同图片且目的地相同，可以用贴图版本收拢。

##### 检查与排错
这是实际修改工程，不同于导出时的临时拆分；同样会先选 Basis。手动移动之后，已分离物体以真实位置为准，旧虚拟叶子不应把它们送回之前隐藏的集合。

### ShapeKey 聚合

<a id="mesh-shape-summary"></a>
#### 在一个列表中调整多个物体的同名 ShapeKey

把同名形态键收进一张表，让由多个物体组成的衣服能一起调整。

**位置：** 网格工具 → 形态键聚合（按集合）。

##### 操作步骤
1. 选择包含目标网格的集合。
2. 等待扫描；结构变化后也可点强制刷新。
3. 调整一行的值，会同步该名字的参与者；编辑行名字，会一起改名。
4. 鼠标悬停 **xN**，查看参与的具体物体。

##### 小案例
身体、上衣、腰带都叫 **FitWide**，列表显示 x3。移动共享滑条会一起调整三者，不会只把衣服变宽却漏掉腰带。

##### 检查与排错
在这里，同名就表示一起控制。某物体需要独立时，应先在那个物体上单独改名。已有 Deform 编号排在前面，其余按自然名称顺序排列。这只整理 Blender 数据，运行时还要设置[游戏 ShapeKey 导出](#game-efmi-shapes)。

<a id="mesh-shape-number"></a>
#### 给自定义 ShapeKey 分配安全的 Deform 编号

给勾选且尚未编号的项目分配运行时编号。已有编号受到保护，会使用最小的可用编号。

**位置：** 形态键聚合 → 左侧复选框 → 自动重命名。

##### 操作步骤
1. 选择正确游戏。鸣潮必须先填写有有效 Metadata.json 的当前对象源。
2. 刷新集合列表，勾选要编号的项目；全选/全不选只影响可改名项。
3. 点击自动重命名。
4. 检查结果，并启用对应游戏的自定义 ShapeKey 导出。

##### 小案例
终末地工程已有 Deform 1 和 Deform 8，选中 **CapeLift** 后可以分到 **Deform 2 CapeLift**，不必从 9 开始。鸣潮还会保留原生范围，因此下一个可用号可能高得多。

##### 检查与排错
左侧勾选表示“要重命名”，不是显示或导出开关。旧面板辅助文字可能写着“未勾选”，以这里说明的实际复选框行为为准。鸣潮缺失或损坏 Metadata 会取消编号，不会冒险占用原生 ID。不要照抄终末地案例数字到鸣潮。

## 权重工具

### 工作对象与传递

<a id="weight-objects"></a>
#### 选好来源、接收网格和可选镜像组

源网格提供某个组的权重分布，目标网格接收它。已经填写对象框之后，不会凭你最后随手选了哪个物体就改变来源。

**位置：** 权重工具 → 工作对象。

##### 操作步骤
1. 源网格选权重正确的参考，选择源顶点组。修改过组列表后可点刷新图标。
2. 目标网格选需要接收权重的衣服或替换件。
3. 检查镜像顶点组。需要双侧时指定对侧组，只做单侧时清空。
4. 需要新建接收骨骼时填写目标骨架。让源、目标的实际表面对齐。

##### 小案例
给袖子制作上臂权重：源是参考手臂，源组是上臂影响，目标是袖子。袖子不会因为当前在视图里被选中就自动变成源。

##### 检查与排错
源候选会排除锁定和特殊组。对象框保存精确名称，找不到时保留名字并变红，同名网格回来后自动连上，X 可以清空。合并后目标仍红，可能要填写合并结果的真实名字，工具不会猜相近名称。

<a id="weight-engine"></a>
#### 选择 Robust 或面插值引擎

两个引擎都从源表面取样，但处理缺口的方法不同。Robust 带有补全：把可靠样本向没有直接匹配的区域延伸。

**位置：** 权重工具 → 传递设置 → 传递引擎。

##### 操作步骤
1. 衣服存在空隙或贴合不均时，可先试 Robust。
2. 若出现安装 Robust 依赖按钮，查看显示的下载大小并执行安装，等它完成。
3. 适合近表面传递时，也可选择 Blender 内置的面插值传递。
4. 先在保存的副本上测试一个接收组，再处理整套衣服。

##### 小案例
紧贴手臂的袖子适合直接面插值；宽松袖口可能受益于 Robust，但仍需要足够可靠的附近样本来带动缺失区域。

##### 检查与排错
当前可选原生依赖清单针对 Windows CPython 3.11，不能自动代表所有 Blender/Python 环境。依赖存放在插件外，不需要额外安装独立 Robust 插件。安装或匹配失败先看完整报告。换引擎不能修正错误骨骼映射或没对齐的模型。

<a id="weight-transfer"></a>
#### 传递一组权重，不偷偷改动其他组

只写采样得到的接收组，以及可选的严格镜像。其他已有组保持原值，即使临时总和超过或低于 1。

**位置：** 权重工具 → 传递设置 → 执行权重传递。

##### 操作步骤
1. 完成[工作对象设置](#weight-objects)。不启用手动接收名时，检查 MMD 表自动推导的目标组。
2. 需要明确指定时才开启手动接收组，镜像接收组也要检查。
3. 要替换的接收组若锁定，先手动解锁。复用/清空选项是固定行为：复用已有未锁接收组，并替换它原来的权重分布。
4. 配置可选平滑，再传递。自动锁定接收组可以保护已经完成的结果。
5. 继续传其他组，最后再做[手动清理](#weight-normalize)。

##### 小案例
某点其他组已有 0.8，本次源采样得到 0.6。传递后两者都保留，总和 1.4，不会为了凑 1 把 0.6 偷偷缩成 0.2。之后由你决定允许哪些组参与调整。

##### 检查与排错
donor 和每顶点组数上限不限制源权重传递。镜像对应缺失或有歧义时会报告并保留目标，不把多层网格平均成一层。写入校验失败会回滚成员关系和锁定状态。在 Blender 创建了新骨骼，也不等于游戏运行时已经支持这根骨骼。

<a id="weight-smooth"></a>
#### 只有采样结果需要时才加平滑

可选平滑只柔化新接收组，然后再由它生成最终镜像，不是自动清理整个网格。

**位置：** 权重工具 → 后处理 → 启用平滑、次数、强度。

##### 操作步骤
1. 先关平滑，看清引擎原始采样效果。
2. 过渡太硬时再打开，从较低强度、较少次数开始。
3. 上次传递后接收组若自动锁定，重复传递前先解锁。
4. 比较关节弯曲与接缝附近的结果。

##### 小案例
袖子的上臂权重在肘部突然断层。可在副本试 **0.2** 强度和几次平滑，与未平滑结果对照。这只是试验起点，不是适用所有模型的标准参数。

##### 检查与排错
次数过多会抹掉有用细节。平滑会阻断跨 UV 接缝传播，因此接缝可能仍是边界。它不规格化其他组；只勾选也不会立即修复已传的值，设置是在执行传递时使用。

### 镜像与组内转移

<a id="weight-mirror"></a>
#### 用明确的成对关系镜像活动组

“镜像权重”是符合导出范围的 Component 网格上的独立整组流程，与下面只修选中顶点的按钮不同。

**位置：** 权重工具 → 镜像映射组。

##### 操作步骤
1. 设置游戏导出集合，把目标 Component 网格设为活动物体。
2. 选择正确一侧作为活动组，检查自动左右识别。
3. 数字或名字不能可靠表达成对关系时，新增手动映射；用减号移除过时的行。
4. 决定是否规格化独立镜像、是否限制组数，再执行镜像权重。

##### 小案例
在你这份源数据里，确认 **12** 和 **18** 是左右一对，登记后选择健康侧为活动组并镜像。换了对象源就要重新确认，不能照抄案例数字。

##### 检查与排错
独立镜像的规格化会保护锁定组，并用符合条件的未锁组分配剩余空间。自动 donor 数量是优先项，不代表只允许这几个组参与。如果只要原样修几个坏点，用[选中顶点镜像](#weight-selected-mirror)，它完全不规格化。

<a id="weight-group-move"></a>
#### 在同一网格内把一组权重转给另一组

把源组数值加到目标组，再清空源组的值。不采样其他网格，也不只是改个名字。

**位置：** 权重工具 → 权重组转移。

##### 操作步骤
1. 让目标网格成为活动物体。
2. 左侧选择来源组，右侧选择另一个已有的目标组。
3. 确保需要改动的组没有被锁定保护。
4. 执行权重组转移，查看完整结果。

##### 小案例
某点多余辅助组是 0.2，正确父组是 0.5。转移后父组变 0.7，该点不再带辅助组的值。

##### 检查与排错
相加超过 1 的值写入时会截到 1，并在报告中计数，因此超过上限时不是无损合并。来源名称可能作为空组留下。方向选反就撤销，先测试关节再清空组名。

<a id="weight-map-merge"></a>
#### 合并指向同一目标的多条映射来源

多组来源确实应该对应同一目标时，把权重归入合适的父级来源，并整理多余关系。它同时修改源权重和映射行。

**位置：** 权重组转移 → 按 MMD 映射合并同目标 / 按通用映射合并同目标。

##### 操作步骤
1. 保存 blend，并导出相应映射表的备份。
2. 检查所有指向同一目标的行，以及源骨架层级。
3. 使用与你实际配置的表对应的按钮：MMD 或通用。
4. 检查保留的父组、清空/移除的源组，以及断开或删除的冗余行。

##### 小案例
袖子上两个辅助影响本来就该对应游戏同一个上臂身份。合并后把影响收在合适父级，不再保留两条竞争同一改名目标的来源。

##### 检查与排错
处理的是该表设置的源对象，不是随便当前选中的网格。若多对一本来就是误配，应修表，而不是用合并把错误坐实。确认变形和导出前保留备份。

### 清理与局部修复

<a id="weight-normalize"></a>
#### 规格化选中顶点，并限制影响数量

可选地裁剪影响数量，再按比例调整已有的可编辑权重。锁定组保持原值，不凭空创建缺失成员。

**位置：** 权重工具 → 后处理 → 按比例规格化选中顶点。

##### 操作步骤
1. 完成需要的传递后，在目标网格进入编辑模式。
2. 只选择需要整理的顶点。
3. 明确解锁允许改变的组；根据目标格式决定是否开启组数限制以及上限。
4. 执行规格化，检查每点总和、组数与变形。

##### 小案例
保护组锁在 0.6，两个可编辑组分别 0.3 和 0.1，刚好填满剩余 0.4。若它们原本为 0.6 和 0.2，按比例整理可以缩回 0.3 和 0.1，同时不动锁定的 0.6。

##### 检查与排错
常见默认四组不是所有游戏的万能规则。锁定值占用已经不可能满足要求时，要人工检查；工具不会偷偷解锁已完成组。规格化也不能把采样错的骨骼变正确，或恢复被错误平滑的细节。

<a id="weight-selected-mirror"></a>
#### 只修复选中的镜像顶点

沿网格局部 X 轴，把健康侧权重原样复制到目标侧，不规格化、不限组数、不改几何，只改目标。

**位置：** 权重工具 → 后处理 → -X 到 +X / +X 到 -X → 镜像选中顶点权重。

##### 操作步骤
1. 如有共享网格数据，先转为单用户，再进入编辑模式。
2. 选健康端或只选损坏目标端都可以，不必把两侧同时选中。
3. 按局部 X 而非屏幕左右选择方向，需要参与的一对组必须两边都解锁。
4. 执行。F9 可调整这次方向，Ctrl+Z 可撤销。

##### 小案例
正 X 一侧袖口的手腕权重坏了，只选这些坏点，然后选择 **-X 到 +X**。负 X 袖口即使没选中，也会作为来源。

##### 检查与排错
只处理已有的互相对应组，中性组沿用同名。无法解释的数字、缺失配对和重合层歧义会跳过。锁定组、源权重、其他顶点、选择、ShapeKey 都不动。受保护组导致两侧总和不同，也不会为了“看着一致”改掉保护值。

<a id="weight-advanced"></a>
#### 先读失败报告，再调整高级设置

高级参数控制哪些表面样本能被接受。先知道失败原因，才知道该改哪个参数。

**位置：** 权重工具 → 高级；传递结果文字与复制图标。

##### 操作步骤
1. 点击查看完整结果，优先核对对象名、接收组锁定、缺失映射和依赖错误。
2. Robust 距离失败时，先检查尺度和对齐，再考虑最大距离。
3. 薄片或反面表面需要检查法线角度和允许法线翻转。
4. 只有确实要比较当前变形时才启用源/目标变形结果；目标求值后的顶点结构仍必须与原网格对应。

##### 小案例
袖口因为物体位置放错，远离参考手腕，正确做法是对齐它。把距离加到连躯干也能采到，只是在掩盖问题。

##### 检查与排错
Point inpaint 改的是缺失区域的补全邻域，不是骨骼身份。Limit dilation 是裁剪影响时的邻域保护，不是传递组数上限。诊断时复制完整报告、保留工程，不能只看到一行完成就当作变形已验收。

### 先做通一个材质

<a id="material-start"></a>
#### 第一个完整案例：替换袖子的贴图

先用一个材质走通全过程，再批量处理衣服。这篇把各操作按新手需要的顺序串起来。

**位置：** 材质工具，以及游戏 → 当前游戏 → 导出 Mod。

##### 操作步骤
1. 准备普通单对象源 EFMI 或 WWMI 工程并另存。对象源目录保留提取原图。
2. 选袖子，激活要处理的材质，执行[初始化](#material-initialize)。
3. 把保存好的新漫反射和法线接到对应输入，检查[各自要替换的原图](#material-original)。
4. 导出 Mod 中开启自动按材质拆分、Slot 风格贴图、使用材质贴图。保留默认模板、完整 INI 输出和复制贴图。
5. 导出到独立测试目录，游戏里确认后再[传播](#material-propagate)到更多材质。

##### 小案例
**Sleeve_D.dds** 是新颜色图，**Sleeve_N.dds** 是新法线。它们的每个用途都要对应袖子 Component 的正确提取原图。不要把 Sleeve_N 选进原图选择器，也不用猜 ps-t 编号。

##### 检查与排错
当前独立材质层不支持 CrossIB、WWMI 跨场景、资产名称匹配、自定义/实时模板、部分导出。普通 Slot 流程支持其中某项，不代表叠加的独立材质层也支持。

<a id="material-initialize"></a>
#### 初始化选中材质

创建插件的用途输入节点，并保留可识别的漫反射和 UV 接线。旧材质作为备份留下，但不承诺完整重现任何复杂着色器的所有预览效果。

**位置：** 材质工具 → 初始化选中材质。

##### 操作步骤
1. 选择正确游戏和对象源。没有对象源也能初始化，但之后要补好原图映射。
2. 在物体模式只选需要处理的网格；操作处理其实际使用的材质。
3. 执行初始化选中材质。
4. 到着色器编辑器检查：用途节点的 Shader 输出应连向活动材质输出。

##### 小案例
MMD 袖子能识别出漫反射，但预览节点很复杂。初始化后，你得到清楚的 Diffuse、Normal 等输入，漫反射原来的坐标路径保留；特殊预览效果需要另外检查。

##### 检查与排错
未选中的使用者保留原内容和槽位。当前编辑副本优先取得原名，旧材质可能变成 **Backup <原名>**。重复初始化已处理材质只刷新映射，不重建接线。撤销或重新指定保留的原材质可以恢复。

<a id="material-inputs"></a>
#### 每个用途输入该接什么图

用途说明的是图片要做什么，不会把任意图片自动转换成那种贴图。Blender 预览也只是对游戏着色器的近似。

**位置：** 着色器编辑器 → 初始化材质的用途输入节点。

##### 操作步骤
1. 为保存好的各张图创建/打开 Image Texture。
2. 从图片节点的 **Color 输出**直接或经过重定向节点接入相应用途。
3. 保持 Shader 连向活动材质输出。
4. 导出前保存绘制或修改过的图片；程序纹理先烘焙为支持的文件。

| 输入 | 通俗含义 |
| --- | --- |
| Diffuse | 表面主要颜色 |
| Normal | 表面细节方向，不是第二张颜色图 |
| Packed PBR（终末地） | 多种材质控制数据装在一张图里 |
| FTM（鸣潮） | 游戏的打包材质控制图 |
| Mask | 控制图，具体作用取决于原着色器 |
| Emission | 用于自发光外观的图片 |
| Light Map / Detail | 原材质确实使用时的额外明暗或细节图 |

##### 小案例
Sleeve_D 的 Color 接 Diffuse，Sleeve_N 的 Color 接 Normal。不要中间插一串程序混合节点，却期待导出器替你还原。Alpha 控制预览，不是独立导出的贴图用途。

##### 检查与排错
Packed PBR/FTM 原样复制字节。未知游戏图不能套通用金属度/粗糙度通道定义。支持已保存 DDS/PNG/JPG/JPEG/TGA/BMP 和打包文件图片，不自动转换格式；脏图、生成图、动画、分块或程序纹理要先保存/烘焙。

### 对应游戏原图

<a id="material-original"></a>
#### 选择这个用途要替换哪张游戏原图

选择器找的是旧游戏图，不是你画的新图。候选唯一时直接应用；确实有多个可能时保持未分配，等你选择。

**位置：** 材质工具 → 当前材质的某个用途 → 选择原始贴图。

##### 操作步骤
1. 设置对应对象源，刷新源映射。
2. 检查每个已接线用途下面显示的原文件名。
3. 错误或未分配时点击该用途，选择真正要替换的提取原图。
4. 不需要额外替换的用途设为保留游戏贴图。导出前检查所有已连接、已启用用途。

##### 小案例
袖子有两张看起来像法线的提取图，一张主表面、一张细节 pass。根据参考与提取证据，给 Sleeve_N 选择主法线。格式一样、颜色相近都不能单独证明身份。

##### 检查与排错
提示结合捕获用途、格式、尺寸与命名，只是辅助，不是固定插槽规则。手动选择保留，每个 Component 各自解决原图和运行位置。红色未分配不是让你随便选第一张消红。

<a id="material-refresh"></a>
#### 刷新原图，而不重建材质

重新读取提取目录当前保留的图片，保留你制作的接线和手动选择。原图是否可用，以源目录顶层实际保留文件为依据。

**位置：** 材质工具 → 刷新源映射。

##### 操作步骤
1. 确认填写的是对象源，不是 Mod 输出。
2. 要用的原图保留在目录顶层；明确排除的可移到备份子目录，不用修改提取 JSON。
3. 对当前材质执行刷新源映射。
4. 检查新增的唯一匹配、手动保留项，以及变为保留游戏贴图的用途。

##### 小案例
之前映射的共享遮罩不想再由这一层替换。把那张提取原图移出源目录顶层并刷新；Blender 节点仍用于预览，但不再自动替换这张已移除原图。文件放回来后，自动推导的映射可以恢复。

##### 检查与排错
明确手选的保留游戏贴图仍是主动退出。刷新不是把新 PNG 复制进游戏的按钮。传播过的映射能跨刷新保留；反复操作优先保持编辑材质原名，不例行累加 .001。

### 传播与持久同步

<a id="material-propagate"></a>
#### 配好一处，再按相同漫反射传播

把其他用途复制给选中且使用同一漫反射的材质。同一图指图片身份或规范化保存路径一致，不是肉眼看起来差不多。

**位置：** 材质工具 → 按相同漫反射传播。

##### 操作步骤
1. 完整配置一份来源材质，同时选择来源和目标网格，让来源材质为活动项。
2. 确认目标使用同一漫反射。选中对象的所有槽位可提供原图证据，真正改动的目标必须被面使用。
3. 不勾覆盖已有连接时，执行传播主要填补空输入。
4. 查看连接、清空、映射和未解决数量；确实要改掉目标已有非漫反射图时才启用覆盖。

##### 小案例
五份袖子材质用同一漫反射。先配一份法线和发光，选五份传播。某目标已有独立改过的法线，填空模式会保留它；空发光可以补上。跨 Component 时，各自仍保留自己的原图对应。

##### 检查与排错
活动的已配置材质优先，否则必须能在所选材质中找到唯一来源。覆盖模式还会清空来源没有的非漫反射用途。填空模式下，从已同步来源移除的用途也会传到选中且仍同步的成员，但不会覆盖已独立改动的非空用途。空图片节点和悬空重定向会断开，不假装有效图片导出。

<a id="material-replace"></a>
#### 从任意成员替换一组同步贴图

传播会记录明确的、按用途划分的成员。以后换图依靠这份成员关系，不是每次全局扫描“长得像”的材质。

**位置：** 材质工具 → 用途的替换路径行 → 文件夹图标；已同步 N 个材质。

##### 操作步骤
1. 点击同步数量，查看这个用途实际包含哪些物体/材质使用位置。
2. 点击替换路径旁的文件夹，选择新保存的图。
3. 检查列出的全部成员，包括当前没选中的物体。
4. 保存 blend；普通改名和保存重开后关系仍在。

##### 小案例
袖子法线传播给五份材质后，只选其中一个成员，把法线替换为 **Sleeve_N_v2.dds**。仍同步的五个法线用途会一起更新，但各自原图身份和 UV 接线不变。

##### 检查与排错
路径栏只是只读信息，不是原图选择器。打包图片显示记录路径，外部文件不一定还在。工具换的是节点图片，不是全局改共享 Image 数据的文件路径。复制物体不会自动入组；手动改节点成为独立编辑，需要明确再次传播才重新参与。

<a id="material-independent"></a>
#### 退出同步、清空原图、保留游戏贴图有什么区别

三个按钮解决三个问题，都不是“删除所有同步成员贴图”。

**位置：** 材质工具 → 各用途的断链、原图重置、原图选择控件。

##### 操作步骤
1. 先确定你要独立编辑、重新选择原图，还是不做额外导出替换。
2. 按下表选择对应动作。
3. 分别检查替换路径、原图状态、同步数量。
4. 三者符合意图后再刷新或导出。

| 操作 | 原图身份 | 图片接线 | 同步关系 |
| --- | --- | --- | --- |
| 退出该贴图同步 | 保留 | 保留 | 只让当前物体/材质的这个用途退出 |
| 清空原图映射 | 回到未分配，也清掉手动退出 | 保留 | 保留 |
| 保留游戏贴图 | 明确跳过这一层额外替换 | 保留给预览 | 保留，但换图不会重新开启导出 |

##### 小案例
一个袖口需要独立法线：先退出法线同步，再换图。如果要让游戏仍用自己的法线，则选择保留游戏贴图。“清空原图”不是永久关闭，刷新可能又推导出来。

##### 检查与排错
其他用途和成员继续同步。保留游戏贴图只跳过独立材质层，不会删除已有 Component/Hash 覆盖。误操作可撤销，批量编辑之前先看作用范围。

### 导出与核对

<a id="material-export"></a>
#### 启用独立材质贴图导出

让不同材质 draw 可以对同一游戏原图使用不同替换，需要足够安全的 Component/pass Slot 证据。

**位置：** 游戏 → EFMI/WWMI → 导出 Mod → Velo 兼容选项。

##### 操作步骤
1. 使用普通单对象源工程和当前 ShaderTextureUsage.json。
2. 开启自动按材质拆分、Slot 风格贴图、使用材质贴图。
3. 运行时兼容时用原生格式读取；有意走旧语法才选模糊模式。保留完整导出、默认模板、写 INI、复制贴图。
4. 先解决接线用途的映射，再导出；检查文件并在游戏比较两块结果。

##### 小案例
袖子和袖口共用一张游戏原漫反射，但需要蓝、白两份替换。分别给材质配置后，各 draw 使用自己的图，而不改变另一块的原图身份。

##### 检查与排错
当前不支持 CrossIB、WWMI 跨场景、资产名称匹配、自定义/实时模板和部分导出。关闭自动拆分会隐藏并完全绕过材质层，不会在后台偷偷推导。未初始化材质保持旧路线，导出不会擅自初始化。

<a id="material-batching"></a>
#### 按贴图聚合 draw，同时保护必要顺序

在最终索引范围生成前，把完整贴图绑定一致的兼容分块放在一起，减少重复设置贴图。

**位置：** 导出兼容选项 → 按贴图聚合绘制；材质工具 → 保留绘制顺序。

##### 操作步骤
1. 开启独立材质贴图；按贴图聚合默认开启。
2. 游戏里确实依赖顺序的材质，勾选保留绘制顺序。
3. 导出，检查透明与前后遮挡。
4. 要对比旧物体顺序时关闭聚合，不必关闭贴图赋值或同步。

##### 小案例
不透明分块使用 A/B/A/B 两套绑定，聚合可变成 A/A/B/B，共用相邻的贴图设置。中间若有受保护透明饰边，它仍是边界，不能把两侧强行跨过去合并。

##### 检查与排错
不跨 Component，保留各物体的 draw 和显隐条件。未初始化、不兼容、已记录透明和 CPU-posed 等路径继续保护。Blender 的 Alpha 接线或 BLENDED 预览不等于游戏混合状态，不会自动取消聚合；已知游戏需要保序时用明确开关。

<a id="material-files"></a>
#### 文件名怎样输出，为什么旧贴图没有更新

替换图按记录的原文件名和扩展名进入 Textures。导出只补缺失文件，不覆盖输出目录已有的同名图。

**位置：** Mod 输出 → Textures，以及 mod.ini 的 filename 引用。

##### 操作步骤
1. 导出前把每张替换图保存为清楚的名字。
2. 避免两张不同来源图使用 Windows 视为相同的目标文件名。
3. 导出后沿着 mod.ini 的实际 filename 检查。
4. 要更新之前已经输出的图，由你明确替换输出文件；或者把源另存为新名，再导出。

##### 小案例
Textures 已有 **Sleeve_D.dds**，是上次导出后你手工画过的。即使源目录同名图字节或尺寸不同，导出仍保留现有图。把下一版源另存为 **Sleeve_D_v2.dds**，就会新增该文件，并更新生成的引用。

##### 检查与排错
不比较输出旧图内容，不自动转换格式，也不清理旧文件。两张待输入源图争用一个名字仍会阻止导出。Resource 节名会清理文件主名，冲突时可能加后缀，但不改变交付文件名。未保存或不支持的图片状态先处理；Blender 预览正确不等于游戏验收完成。

### 从这里开始

<a id="game-start"></a>
#### 安装、更新与第一个工程

Velo 是 Blender 侧工具，还需要匹配的游戏加载器和有效捕获。安装插件不会顺便安装或配置游戏端环境。

**位置：** Blender 偏好设置 → 插件；3D 视图 → N → Velo Tools。

##### 操作步骤
1. 从发布附件下载 **velo_tools-1.7.1.zip**，不是 GitHub 自动提供的源码压缩包。
2. 偏好设置 → 插件 → 从磁盘安装，选 zip 并启用 Velo-Tools。
3. 在视图按 N 打开侧栏，游戏 Tab 选择目标游戏。
4. 按对应提取、导入、导出教程操作，第一次只做小测试。

##### 小案例
第一个终末地工程先导入原模型，做一个明显且可恢复的小改动，导出测试副本。不要一上来替换整套衣服后才第一次确认流程。

##### 检查与排错
声明最低 Blender 3.6，主要测试环境是 4.4；可选 Robust 依赖支持范围更窄。更新使用偏好设置里的 Velo 总更新器，完成后重启，不单独更新内置 EFMI/WWMI。独立工具可以共存。开发目录联接安装不能点更新器，否则替换会碰到源码仓库。

<a id="game-files"></a>
#### 分清五个工作阶段

很多导入导出问题其实是目录填错。对象源描述原游戏，输出目录装你的新 Mod，不是同一种东西。

**位置：** 提取、导入、导出各目录框。

##### 操作步骤
1. 保留新鲜 **Frame Dump**：捕获的 Buffer、贴图、draw 信息，通常还有 log.txt。
2. 提取成 **对象源**：Component 文件、Metadata、贴图证据。
3. 只有 WWMI 跨场景流程才额外生成 **合并对象源**。
4. 导入到 Blender **组件集合**，保存 blend。
5. 导出到单独 **Mod 输出**，不要反过来把输出作为自己的对象源。

##### 小案例
建立同级 **Capture**、**Source**、需要时的 **MergedSource**、以及 **ModOutput**。普通工程跳过 MergedSource；跨场景工程以后从合并根目录导入导出，不再回到旧子源。

##### 检查与排错
Metadata.json 管几何与骨骼，TextureUsage.json 管基础图片用途，ShaderTextureUsage.json 增加着色器/Slot 捕获证据。骨骼名旁车、CrossIB.json、CrossSceneManifest.json 都要跟对应源一起保存。证据过时就重新生成，不手造 JSON，也不从图片像素猜游戏 Hash。

### 终末地 · 原始 EFMI 流程

<a id="game-efmi-extract"></a>
#### 提取终末地对象源

把捕获变成可编辑的 Component 文件，以及以后导出所需的证据。提取角色不是随便打开一个贴图文件夹。

**位置：** 游戏 → 终末地 → 模式：提取帧数据。

##### 操作步骤
1. Frame Dump 目录指向包含目标的新捕获。
2. 指定输出目录，留空则写到 dump 位置。
3. 检查[过滤选项](#game-efmi-filters)；之后要做 Slot 时保留跳过 Dirty Slot。
4. 计划 CrossIB 时开启生成 CrossIB.json；想马上检查可开启提取后导入。
5. 执行提取，查看报告与生成的各角色目录。

##### 小案例
在需要的主精度视图捕获角色，提取后找到含 Component 文件和 Metadata.json 的那一个角色目录。它才是导入源，不是外面装着多个角色的父目录。

##### 检查与排错
容忍提取错误会跳过失败对象，部分成功不能当作完整来源。Velo 分开保存制作使用的紧凑编号与运行时映射，应一起保留。旧数据需要重新提取，不借用另一个对象的表。

<a id="game-efmi-filters"></a>
#### 过滤提取内容，而不误删需要的部件

过滤器只缩小捕获范围，不知道某部位对你是否重要；部分过滤还会改变最终 Component 编号。

**位置：** EFMI 提取帧数据 → 对象/组件/贴图过滤与 Velo 兼容选项。

##### 操作步骤
1. 使用新输出目录，避免把上次残留当成本次结果。
2. 按需用静态对象、最小组件/贴图数量或明确资源 Hash 缩小对象范围。
3. 理解编号后再填组件保留/跳过范围；跳过优先。
4. 检查实际保留内容，以及重新连续排列的 Component 编号。

| 选项 | 要检查的影响 |
| --- | --- |
| 自动跳过 LOD 组件 | 默认不启用；最终编号前移除没有原始 PS 贴图绑定的 draw |
| 组件保留/跳过 | 可填 0,1,5-7，使用自动 LOD 过滤后的编号 |
| 资源 Hash 定向 | 开启且明确填写目标时，绕过自动 LOD 过滤 |
| 跳过小贴图/JPG | 可能移除有用图，不应只为目录清爽就开启 |
| 跳过 Dirty Slot | 只有日志证据可用时才移除继承下来的过时绑定 |

##### 小案例
保留 **0-8**、跳过 **4,6**，留下过滤后编号 0-3、5、7-8，再重新编号。原先按旧 Component 7 命名的替换网格，需要对新源重新核对。

##### 检查与排错
日志证据不可用时，Dirty Slot 过滤会保留旧式输出，不乱猜删除。原图缺失应回到提取调查，不是把新图映射到另一张无关图片来糊弄通过。

<a id="game-efmi-import"></a>
#### 导入终末地 Component

把提取模型导入，决定顶点组身份是跨部件共享，还是各部件独立。

**位置：** EFMI → 模式：导入对象。

##### 操作步骤
1. 对象源指向提取出来的角色目录。
2. 选择顶点颜色存储，以及 Merged 或 Per-Component 导入。
3. 按需开启组件子集合，会生成 C0、C1 等。
4. 保留导入贴图便于看原图；镜像网格应与预期方向一致。
5. 导入后检查几何、组、材质和集合结构。

##### 小案例
整套服装想用共享制作身份，可选 Merged；有意按每个部件本地数字工作，才选 Per-Component。

##### 检查与排错
Merged 要求相应 Metadata v4 映射。想带骨骼名字导入，先生成[命名骨架文件](#game-efmi-names)，再开启兼容选项里的导入骨骼名映射与骨架，该选项默认关闭。导入子集合后，导出不能忽略这些嵌套集合。

<a id="game-efmi-names"></a>
#### 为终末地生成带名字的骨架

用对应的解包 LOD0 资产，把原始骨骼名字和有方向的层级带进 Merged EFMI 工程。

**位置：** 游戏 → 终末地 → 骨骼名映射；导入对象的兼容选项。

##### 操作步骤
1. 设置匹配的 EFMI 对象源。
2. 选择一个 LOD0 GLB，或受支持的、包含一个 Avatar 以及原始 Unity YAML LOD0 Mesh/prefab 的角色根目录。
3. 生成骨骼名映射，把 **BoneNameMapping.json** 和 **BoneNameSkeleton.glb** 与源一起保存。
4. 选择 Merged 导入，勾选导入骨骼名映射与骨架；按需启用 .L/.R 成对改名。

##### 小案例
数字袖子不好摆姿势，用同角色原始 LOD0 生成映射，再导入一个新测试集合，得到有名字的组和骨架修改器。

##### 检查与排错
1.7.1 用完整对应蒙皮权重证明身份，旧 v1 旁车要重新生成 v2。不向父级或旁边文件夹乱找 GLB。歧义或证据缺失应解决来源，不能借另一 Component 的局部骨骼表。

<a id="game-efmi-export"></a>
#### 选对骨架模式，导出终末地 Mod

三个导出选择对应不同运行时编号，要根据导入和制作方式选择，不只看名字里都有 Merged。

**位置：** EFMI → 模式：导出 Mod。

##### 操作步骤
1. 设置组件集合、对应对象源和独立 Mod 输出目录。
2. 按下表选择模式；首次保留完整 INI 和复制贴图。
3. 检查[范围与材质拆分](#game-scope)，暂不打开无关高级功能。
4. 导出，查看报告，再到游戏测试。

| 模式 | 含义 |
| --- | --- |
| Merged（统一顶点组） | 共享制作编号在导出时转回每个 Component 的本地运行编号 |
| Per-Component（部件独立） | 工程本来就在使用各部件自己的组 |
| Merged（合并骨架） | 共享编号/名字通过对象源已确定映射，进入合并骨架运行时 |

##### 小案例
Merged 导入的工程通常把下次导出默认设成合并骨架。只有明确想用“共享制作、旧部件独立运行时”，才手动选另一个 Merged 选项。

##### 检查与排错
有权重身份无法解析会阻止导出，给物体换 Component 去借无关映射不是修复。1.7.1 自动给目标合并骨架资源补足缺失读取/写入能力，避免文件夹名字影响显示；上游已显式完整声明时原样保留，导出不联网检查。游戏真实表现仍需单独测试。

<a id="game-efmi-lod"></a>
#### 添加终末地远距离 LOD

LOD 是游戏在远处使用的另一套几何。近景捕获不能代表所有距离。

**位置：** EFMI → 模式：提取 LOD 数据。

##### 操作步骤
1. 先提取主对象。
2. 在目标距离几何实际被绘制时捕获。
3. 填入 LOD Frame Dump 和已有对象源。
4. 先用默认匹配提取，读清失败原因后再改过滤或匹配。
5. 导出并测试近远切换。

##### 小案例
改过的外套近景正常，远处却回到原版。补入真正远距离 LOD 证据，再导出并检查两种距离。

##### 检查与排错
覆盖是可选项，替换冲突 LOD 数据应整体替换，不混留旧记录。未匹配部件可能保留标记为缺席的全精度回退，这不等于抓到了真实 LOD。“允许无 LOD 导出”只是绕过要求，不会改变游戏距离行为。

### 终末地 · Velo 扩展

<a id="game-efmi-crossib"></a>
#### 用 CrossIB 借另一 Component 的绘制通道

CrossIB 把指定来源几何借给另一 Component 的渲染通道。它不是鸣潮跨场景合并，而且箭头有明确方向。

**位置：** EFMI 导出 Mod → Cross Index Buffer。

##### 操作步骤
1. 使用完整导出，开启 CrossIB。
2. 确保源里有 CrossIB.json v2；生成/重新生成会要求选择当前相关 Frame Dump。
3. 一个网格用物体映射，一组已规划网格用集合映射。
4. 填写右侧目标 Component，再导出。
5. 游戏中检查借用通道与普通部位。

##### 小案例
一块饰边需要经过兼容的另一 pass 绘制：饰边是左侧来源，借用它的 Component 是右侧目标。反过来填写就变成另一个请求。

##### 检查与排错
重新生成替换一份证据，不合并不相干场景。dump 不包含目标时会拒绝且保留原证据。有映射时输出采用 200-205 能力约定的 CrossIBClassifier.ini。不要与当前不支持它的独立材质贴图层混用。

<a id="game-efmi-shapes"></a>
#### 导出终末地自定义 ShapeKey

把明确编号的形态键变成运行时控制。普通无编号键仍按当前值作为制作好的基础形状。

**位置：** EFMI 导出 Mod → 高级 → 导出自定义 ShapeKey。

##### 操作步骤
1. 在导出集合网格创建例如 **Deform 12 CapeLift**。
2. 开启导出自定义 ShapeKey，正常使用保留合并 Buffer 文件。
3. 看实时检测列表，点击条目定位物体。
4. 解决同一物体重复 ID、多个参与者初始值冲突，再完整导出。

##### 小案例
Deform 12 CapeLift 设为 0.375，输出持久变量 **$ShapeKey_12** 以此初始化，而基础位置 Buffer 对这个运行时键保持中性。无编号 Fit 键设 0.2，则会烘入导出基础形状。

##### 检查与排错
Deform2Blink 这类空格/大小写变体可识别，但身份取数字。同 ID 在多个部件共用控制。合并 Buffer 时每 Component 额外两份合并文件，不随键数增加；关闭时使用旧逐槽文件。只在网格汇总里看到键，不代表运行时导出已启用。

### 鸣潮 · 原始 WWMI 流程

<a id="game-wwmi-extract"></a>
#### 提取 WWMI 角色与贴图

在目标几何和贴图形态实际可见时提取。一个形态、一个距离的捕获，不代表其他所有状态。

**位置：** 游戏 → 鸣潮 → 模式：提取帧数据。

##### 操作步骤
1. 设置新鲜 Frame Dump 和输出父目录。
2. 检查小贴图、JPG、已知 cubemap、同插槽同 Hash 过滤。
3. 保留跳过 Dirty Slot，用证据清理过时继承绑定。
4. 执行提取，检查目标对象目录、Metadata、贴图、ShaderTextureUsage.json。

##### 小案例
先提取近距离基础形态。另一形态只换贴图时，之后用[形态贴图合并](#game-wwmi-forms)，不要手改基础 JSON。

##### 检查与排错
有用图片没了可能是被过滤。Dirty Slot 只在证据有效时保留已证明的特殊继承用途，不是保留所有挂着的槽。日志不可用时保留旧式输出。缺少面部 ShapeKey 数据通常应在表情动画时重新捕获，而不是不检查就开启高级缺失数据放行。

<a id="game-wwmi-import"></a>
#### 导入 WWMI 网格与原图预览

普通工程从提取角色目录导入；跨场景工程从最终合并根目录导入。制作期间保持编号约定一致。

**位置：** WWMI → 模式：导入对象。

##### 操作步骤
1. 选择正确对象源。
2. 选择顶点颜色存储，以及 Merged 或 Per-Component 导入。
3. 按需启用组件子集合与导入贴图。
4. 镜像网格设置与预期左右方向一致。
5. 导入后检查组件树和顶点组名。

##### 小案例
先以 Merged 把服装导入 C0/C1 等集合。如果有匹配解包资产，再用[原始骨骼名映射](#vg-wwmi-map)。

##### 检查与排错
贴图预览优先 ShaderTextureUsage.json，再回退 TextureUsage.json。预览缺失不自动等于几何缺失。跳过空顶点组改变的是列表，不是把局部骨骼身份转换成共享身份。

<a id="game-wwmi-skeleton"></a>
#### 选择 Merged、Per-Component 或 from-Merged

导入有两种制作布局，导出另有第三条路线，把共享制作组转换成局部运行组。

**位置：** WWMI 导入/导出 → 骨架模式。

##### 操作步骤
1. 先决定制作是否需要跨 Component 共享组。
2. 按该约定导入。
3. 按下表选择导出策略。
4. 在游戏检查动画，以及相关的多同角色同屏情形。

| 策略 | 用途与取舍 |
| --- | --- |
| Merged | 共享制作、跨部件权重和骨架缩放；原生运行时有一帧延迟，同目标多实例时会暂停 |
| Per-Component | 局部制作/运行，无一帧延迟；骨骼范围受限，不支持自定义骨架缩放 |
| Per-Component（from Merged） | 共享制作转局部运行，严格检查每部件可用骨骼 |

##### 小案例
想方便地用共享组编辑，但希望游戏用局部运行方式，就 Merged 导入、from-Merged 导出。如果袖子带了允许表以外的骨骼权重，应修正影响，不绕过错误。

##### 检查与排错
已经按局部编号制作的数据不要选 from-Merged。只看数字组名无法判断编号体系，必须与原始 Metadata 和模式一致。

<a id="game-wwmi-export"></a>
#### 完整导出 WWMI Mod

普通导出根据配置集合和源，生成完整 mod.ini 与数据。第一次导出不应走部分导出。

**位置：** WWMI → 模式：导出 Mod。

##### 操作步骤
1. 设置组件集合、制作所用的精确对象源和独立输出目录。
2. 选择[骨架策略](#game-wwmi-skeleton)。
3. 保留复制贴图、写 mod.ini 与有用注释。
4. 检查集合显隐和自动按材质拆分。
5. 导出后查看最终报告、Meshes、Textures、mod.ini。

##### 小案例
只改了一段袖子，也先完整导出到测试 Mod，确认身体和袖子一起正常加载，再考虑更快的仅 Buffer 更新。

##### 检查与排错
默认贴图替换是 Hash，是否选 Slot 另行决定。自动拆分在普通、from-Merged、跨场景都遵循完整启停规则。预处理使用临时副本，不需要为了每次导出永久改掉所有制作对象。

### 鸣潮 · Velo 扩展

<a id="game-wwmi-lod"></a>
#### 提取 WWMI LOD 数据

给已有对象源补入其他距离的几何证据。LOD 是独立面板，不是再对同目录做一遍普通基础提取。

**位置：** 游戏 → 鸣潮 → LOD 数据提取。

##### 操作步骤
1. 先有主对象源，再在目标 LOD 可见时捕获。
2. 设置 LOD dump 和已有 WWMI 对象源。
3. 首次保留默认匹配，确有需要才使用 Hash/最小顶点过滤。
4. 提取，完整导出，测试距离切换。

##### 小案例
头发近处正确，中距离回原版。捕获中距离模型并补 LOD，再反复走近走远检查。确认中距离修好后，也没有破坏原本正常的近景。

##### 检查与排错
已有 LOD 默认保护，勾选覆盖才替换。高级参数包括体素/点云方式、误差、采样/体素大小、候选数，应按失败原因调整。换了源骨架或跨场景来源后重建相关 LOD，不移植旧映射。

<a id="game-wwmi-crossscene"></a>
#### 把多个场景 IB 路线合成一个制作源

同一目标在不同场景使用不同 IB 路线时，使用跨场景合并。IB 代表索引/绘制路线，不是贴图文件。

**位置：** 游戏 → 鸣潮 → 跨场景合并。

##### 操作步骤
1. 准备一个基底提取目录，以及每个额外场景的提取目录。
2. 设置基底，添加来源行，并按下表选角色。
3. 指定全新输出目录，执行跨场景合并。
4. 用普通 WWMI 导入读取合并根目录，之后导出也一直使用这个根。
5. 每个场景都测试冷进入和切换后的表现。

| 角色 | 制作时是什么 |
| --- | --- |
| 折入基底 Fold | 用基底几何代表该路线；Buffer 不兼容时可保留独立 Buffer 路径 |
| 独立可编辑 Editable | 保留独立几何与制作身份 |
| 形态合并 Merge Form | 同 vb0 且结构一致的提取，只给一个 Fold 行补贴图形态证据，不复制几何 |

##### 小案例
以展示场景为基底，折入兼容的大世界路线。真正几何不同的形态应放 Editable，不要强行当成纯贴图合并。

##### 检查与排错
自包含根目录有 Metadata、STU、Component 文件和 CrossSceneManifest.json v3，不依赖 scene_ibs 子目录。旧 routing-v2 源要重新合并。_ibN 是归属标签，不是另一套本地部件编号。不支持自定义/实时模板和独立材质贴图层。

<a id="game-wwmi-forms"></a>
#### 不复制几何，只补另一个贴图形态

从额外形态的原始 dump 补贴图证据到已有源。适用于相同几何身份，不能代替独立可编辑形态。

**位置：** 游戏 → 鸣潮 → 形态贴图合并。

##### 操作步骤
1. 等额外形态贴图加载好，近距离捕获。
2. 设置形态 dump、当前对象源、稳定的形态标签。
3. 执行合并形态贴图数据。
4. 其他形态或距离重复操作。同一形态积累证据复用同标签，基础形态使用 base。

##### 小案例
同一服装进入强化状态会换图，用 **powered** 合并该捕获。以后更远距离的强化捕获仍叫 powered，不造一个假的新形态。

##### 检查与排错
操作更新 STU 并保留所需形态图。当前跨场景根会通过 manifest 部件映射更新根证据，不写子 STU。不同 vb0 或结构不同的几何应独立处理。验收要反复切形态并触发贴图流送，不只看一张静止画面。

<a id="game-wwmi-anchors"></a>
#### form 锚点只能当辅助证据

锚点是“某形态出现了”的捕获信号。它能缩小已有安全分支，不能拯救本来就无法从局部 Slot 区分的形态。

**位置：** WWMI Slot 兼容选项 → formid 辅助判据和锚点查找器。

##### 操作步骤
1. 首次安全 Slot 导出先保持关闭。
2. 确实需要时，设置基础 dump，添加带标签的额外形态 dump 行。
3. 查找候选、检查并应用目标；换捕获后重置候选。
4. 测试全部形态，包括没有可见锚点的形态。

##### 小案例
已经证明属于某形态的 vb0，可按 **1234abcd:powered** 格式填写。这里只演示 Hash:标签语法，不是你角色的可用身份。

##### 检查与排错
手填支持八位 vb0 Hash、十六位像素着色器 Hash，不接受拿 IB 或顶点着色器 Hash 代替。恰好只有一个形态没有锚点时，可在其他锚点都未出现时排除确定。游戏更新后刷新，不随便借 UI/VFX 信号。

<a id="game-wwmi-shapes"></a>
#### 导出 WWMI 自定义 ShapeKey，同时保留原生形变

哪些 Deform ID 属于原生，由对象源 Metadata 决定。自定义位置变化单独叠加，不取代游戏原生形变链。

**位置：** WWMI 导出 Mod → 导出自定义 ShapeKey；编号在网格工具完成。

##### 操作步骤
1. 选择正确源，用[安全自动编号](#mesh-shape-number)。
2. 需要自定义控制时保留导出开关，普通和跨场景默认开启。
3. 同数字 ID 的多个参与者使用一致初始值。
4. 完整导出，同时测试原生表情和自定义控制。

##### 小案例
创建 **CapeLift**，让编号工具从该源保留范围外找空号。输出变量是 **$ShapeKey_<所分配ID>**，初值来自 Blender。当前列表没看到 1，不代表 1 就可以用。

##### 检查与排错
每个原生 batch 保留 127 个 ID。关掉自定义导出只移除外部控制，不会把它们塞回原生 Buffer。没有有效自定义位移就不生成空资源。无编号键按当前值烘入 Basis。d3dx_user.ini 旧持久值可能覆盖新默认值；初值冲突阻止导出，部分导出不能独立更新整条链。

<a id="game-wwmi-raw"></a>
#### 提取、编辑、导出 Raw Mesh

Raw Mesh 面向普通蒙皮角色检测链以外的适合特效、场景、静态几何，不是绕过角色提取错误的通用捷径。

**位置：** 游戏 → 鸣潮 → 原始网格工具。

##### 操作步骤
1. Raw Mesh 提取模式填写 dump、输出目录、逗号或换行分隔的 VB/IB Hash。
2. 自动识别没问题就留空 Position 元素，失败才明确指定。
3. 提取后切到 Raw Mesh 导入，选择生成目录。
4. 编辑副本；导出时选择集合、输出和 Auto/Faithful/Rebuild。
5. 游戏中检查目标几何以及其他捕获效果。

| 模式 | 允许怎样改 |
| --- | --- |
| Auto 自动 | 拓扑没变走保真，否则重建 |
| Faithful 保真 | 重编码位置，其他保存字节原样传递，拓扑必须不变 |
| Rebuild 重建 | 可以改拓扑，非标准数据尽力重建，可能有损 |

##### 小案例
只移动静态飘带原有点，不改三角形，保真是可控试验。增加细分则需重建，并重新检查 Blender 不能准确表达的属性。

##### 检查与排错
VB Hash 选其整个对象与 draw，IB Hash 选匹配 draw/部件；歧义 Hash 会拒绝。保真发现拓扑不兼容就停止，不会猜顶点对应。输出是独立普通 3Dmigoto 覆盖，不是标准角色骨架运行时。

### 贴图策略与通用导出选项

<a id="game-texture-strategy"></a>
#### 在 Hash、Slot、资产名称匹配之间选择

这三种是识别贴图该换在哪里的方法，不是三种图片格式。

**位置：** 游戏 → 导出 Mod → Velo 兼容选项。

##### 操作步骤
1. 捕获身份稳定适用时，先使用原生 Hash 替换。
2. 有新鲜绑定证据、需要处理流送或身份变化时，考虑 [Slot](#game-slot)。
3. 鸣潮资产名匹配需要带 TextureAssetManifest.jsonl 的捕获，重新提取后开启使用资产名称匹配。
4. 检查相关形态和距离，不只看刚加载那一刻。

| 模式 | 依赖什么证据 |
| --- | --- |
| Hash | 捕获到的贴图资源身份 |
| Slot | 能安全区分运行分支的 Component/pass 绑定与格式 |
| 资产名（鸣潮） | 保留输出贴图记录里真实捕获的完整资产路径 |

##### 小案例
一张外观相同的图在流送后 Hash 变了，重画像素不会找回缺失身份。应捕获该状态，再使用新证据支持的路线。

##### 检查与排错
资产名和 Slot 互斥。资产名输出用捕获短名；已知短名相同但完整路径不同会拒绝。没有路径证据的记录继续走原生 Hash，不从文件名编造资产路径。

<a id="game-slot"></a>
#### 开启 Slot 贴图，并选择哪些 Component 使用

在正确部件 draw 期间绑定替换图，之后恢复先前状态。插槽来自捕获证据，不从新图片颜色猜。

**位置：** EFMI/WWMI 导出 Mod → Slot 风格贴图 → 导出模式与组件列表。

##### 操作步骤
1. 重新提取当前对象源，确认有有效 ShaderTextureUsage.json 和格式证据。
2. 开启 Slot。默认用原生格式读取，ps-tN->Format 语法要求 XXMI Libs 1.1.0 或更新；有意兼容旧语法才用模糊格式匹配。
3. 点击列出组件，取消要保留 Hash 的部件。从未填充的空列表表示全部符合条件部件。
4. 使用支持的模板导出，同时测试开启和退出的部位。

##### 小案例
身体需要 Slot，某配饰应继续 Hash。填充列表后取消配饰，而不是关闭整个 Mod 的 Slot。

##### 检查与排错
刷新保留旧选择，新部件默认选中。退出部件共享的 Hash 可能仍需全局原生覆盖。缺格式、分支歧义或必要 draw 范围会阻止导出，不放宽条件硬求成功。空 ResourceBypassPST 是运行时备份引用，不是要删除的垃圾。

<a id="game-scope"></a>
#### 控制导出什么：名字、集合与材质拆分

组件集合是导出根，显隐/嵌套决定哪些对象参与，材质拆分决定符合条件的几何如何分配。

**位置：** 导出 Mod → 组件集合、忽略选项、自动按材质拆分。

##### 操作步骤
1. 把要导出的网格放在配置根下面。
2. 检查忽略嵌套集合、隐藏集合、隐藏物体。
3. 自动拆分开启时，检查材质前缀和规划目的地。
4. 关闭时，每个完整导出物体自身必须带正确 Component 名。
5. 导出后核对全部目标，不只确认输出目录不为空。

##### 小案例
C0/C1 是子集合，忽略嵌套可能导致完全没东西导出。隐藏祖先也会排除看起来没隐藏的孩子。袖子拆开后在 Outliner 移动，真实集合位置应保持权威。

##### 检查与排错
开启用临时材质感知预处理；关闭则全程绕过材质路由，包括独立材质覆盖。但不关闭 MMD 映射、ShapeKey、修改器或骨骼校验。多个集合链接按有效、可见、在范围内的路径决定，不任取一条隐藏链接。

<a id="game-advanced"></a>
#### 原始工具里的高级选项分别做什么

高级开关会改变数据或运行行为，不是“全勾画质更好”的检查表。

**位置：** EFMI/WWMI 导出 Mod → 主选项与高级。

##### 操作步骤
1. 保留可用基线，一次只改相关选项。
2. 按表判断控件实际改变什么。
3. 涉及 INI/运行行为时完整导出。
4. 在受影响条件下比较几何、动画和显隐。

| 控件 | 含义 |
| --- | --- |
| 镜像网格 | 镜像数据以匹配游戏方向，不只是物体 Scale X |
| 应用全部修改器 | 导出时使用预期修改器结果，注意拓扑和 ShapeKey 相互影响 |
| 忽略禁用 ShapeKey | 在相关求值/导出路径排除被禁用的键 |
| 补齐顶点组 | 添加数字占位，不创造权重 |
| 补齐网格数据 | 添加游戏特定默认层，WWMI 与 EFMI 默认不同 |
| 骨架缩放 | 在所选模式支持时调整游戏中模型尺度 |
| EFMI 最大实例数 | 合并骨架多实例容量，会预先占用内存 |
| EFMI 空间识别 | 为加权对象用位置证据确认部件归属；阈值要符合可用独有组件数 |

##### 小案例
测试运行时缩放，保留支持的 Merged 模式，从 1.0 做小幅变化比较。不要同时打开无关缺失数据或身份选项。

##### 检查与排错
WWMI 原有 Unrestricted Custom Shape Keys 不等于 Velo 独立自定义 ShapeKey 开关。缺失数据放行不会补出可靠捕获。保留临时物体、重新加载时导出等调试选项用于诊断，不是常规发布配置。

<a id="game-mod-info"></a>
#### 填写 Mod 名称、作者、链接和 Logo

用原始 Mod Info 面板描述交付作品，这些信息不决定导出哪些几何。

**位置：** EFMI/WWMI 导出 Mod → Mod 信息。

##### 操作步骤
1. 填写名称、作者、说明和链接。
2. 使用 Logo 时准备 **512×512、BC7 SRGB 的 DDS**。
3. 指定 Logo 并完整导出。
4. 检查 Textures/Logo.dds 与生成的引用。

##### 小案例
给服装起清楚标题，链接到发布说明。Logo 应真正按要求编码，不是把 PNG 后缀改成 .dds。

##### 检查与排错
改扩展名不等于转换格式。WWMI 跨场景只保留一份共享 Mod 信息，各 IB 仍有自己的注册。部分导出不会交付完整元数据和附件。

<a id="game-toggles"></a>
#### 制作一个简单的物体显隐开关

INI 开关改变状态变量，让指定物体在某状态可见。它不是交互 GUI 制作器。

**位置：** EFMI/WWMI 导出 Mod → INI 开关。

##### 操作步骤
1. 启用 INI 开关并添加变量，起清楚名字，在编辑变量中设置不冲突的快捷键。
2. 添加状态，把目标物体放入应显示的状态。
3. 核对默认状态，学习阶段暂时显示空状态和默认条件。
4. 完整导出，在游戏逐个循环状态。

##### 小案例
创建 **coat_style**，一个状态显示 CoatLong，另一个显示 CoatShort，身体不参与这组选择。检查切键只换长短外套，不把身体一起藏掉。

##### 检查与排错
空格组合按键，分号分开多个可替代组合。高级条件 AND 优先于 OR，要检查组合含义。展开收起只影响编辑显示。导入导出在文本编辑器中用 JSON，导入前看清替换/清空变量选项；删变量、状态或物体条目之前备份。

<a id="game-templates"></a>
#### 只有准备维护完整规则时才用自定义 INI 模板

自定义 Jinja2 模板可以替换整个生成结构，不只是安全地在默认输出末尾加一行。

**位置：** 普通单源导出 Mod → INI 模板。

##### 操作步骤
1. 普通制作保持默认模板。
2. 有意开发模板时，先保存已有输出，再选择 Blender 文本块或外部模板。
3. 打开编辑器做一个受控修改。
4. 实时更新只指向确定的测试输出，切换工程或导出其他 Mod 前先停止。

##### 小案例
熟悉 INI 的作者在私有测试模板增加一条展示注释，先比较完整输出与基线，再尝试真正运行逻辑修改。

##### 检查与排错
旧模板可能漏掉新版资源。WWMI 跨场景由直接编译器负责完整多 IB 结构，所以拒绝自定义/实时模板。Slot 转换和独立材质层也有模板限制。恢复默认并完整导出，才回到维护好的路线。

<a id="game-partial"></a>
#### 部分导出只用于明确的 Buffer 更新

把指定 Buffer 写进已经完整的 Mod。部分导出不生成 INI、不复制附件，产物不能单独发布。

**位置：** WWMI 导出 Mod → 高级 → 部分导出 → Buffer 选择。

##### 操作步骤
1. 先有一份保留的、确认可用的完整导出。
2. 确认究竟改了什么，已有 INI 和未变资源仍匹配。
3. 开启部分导出，只选所需类别：索引、位置、骨骼混合、向量、颜色、UV 或支持的形态数据。
4. 测试更新，发布前或结构/功能改变后回到完整导出。

##### 小案例
熟悉流程的作者只改兼容的位置数据，明确只更新位置 Buffer。若同时改了拓扑或 draw 范围，只更新位置就不够。

##### 检查与排错
新材质路由、自定义 ShapeKey 整链变化、新独立包都不适合部分导出。这个模式没生成新 INI 是预期行为。保留之前完整目录，Buffer 不匹配时才能恢复。

### 输出、排错与参考

<a id="game-output"></a>
#### 检查输出，并保留作者管理的贴图

完整导出通常包含 mod.ini、Meshes、Textures，以及可选辅助 shader。成功消息之后还需要文件和游戏检查。

**位置：** Mod 输出目录与游戏加载器。

##### 操作步骤
1. 读最终报告，审计错误应当作失败。
2. 确认 INI 引用的每个文件都存在。
3. 检查实际加载的是目标图，不是之前同名输出。
4. 测试冷加载、重载、切角色、各场景/形态，以及需要的近远状态。

##### 小案例
新源图没有显示，因为输出已有作者编辑过的同名图。按[交付规则](#material-files)决定保留还是明确替换，再测试。

##### 检查与排错
标准 Component DDS/JPG 由提取/导出管理，自制遮罩等附属图由作者负责。跨场景根的标准文件名必须与 STU 所有权一致；从根移除原图会把它排除出新生成路线，输出旧文件可能还在但不再被引用。静态检查不证明游戏画面使用了替换。

<a id="game-troubleshoot"></a>
#### 按失败阶段排查，不乱改无关设置

先判断问题在捕获、生成源、Blender 制作、导出还是运行时，再修对应阶段。

**位置：** Blender 完整操作报告、配置目录与相应教程。

##### 操作步骤
1. 记录操作和完整消息，另存工程。
2. 根据下表选择下一步。
3. 用最小相关改动复现，重新导出到受控目录。
4. 同时比较修复目标与之前正常的一项功能。

| 现象 | 优先检查 |
| --- | --- |
| 看不到游戏面板 | 插件启用、顶部 Tab/游戏、更新后重载或重启 |
| 没找到 Component | 导出根、嵌套/显隐、Component 名 |
| 映射缺失或过时 | 正确源、重新提取或生成 v2 骨骼名 |
| 贴图不变 | 实际输出文件名、旧同名图、原图选择、导出模式 |
| Slot 导出被拒 | 当前 STU、必要格式、分支能否区分 |
| 镜像没效果 | 局部 X 方向、选中端点、两侧组是否解锁 |
| ShapeKey 不能控制 | 编号、原生保留范围、开关、有效位移、持久值 |
| 换场景/距离失效 | 捕获相应路线/形态/LOD，不复用无关证据 |

##### 小案例
合并物体后来源框变红，这是精确名字找不到，不是权重引擎坏了。选择真实合并名或恢复所需同名网格，再重试。

##### 检查与排错
支持撤销的制作操作可撤销，大范围恢复用保存的工程/输出副本。多阶段导出失败后不要默认输出毫无变化，发布前检查文件。工具结果不能替代你准备支持的真实游戏条件验收。

<a id="game-glossary"></a>
#### 只认识实际用得到的几个术语

把术语理解成具体文件或操作，不需要先学完整渲染引擎才能看懂教程。

**位置：** 五个 Tab 共用的参考。

##### 操作步骤
1. 遇到不认识的词先查表。
2. 对照当前目录、物体或操作。
3. 回到教程，只改相关控件。

| 术语 | 通俗含义 |
| --- | --- |
| Component | 提取部件/绘制身份，不是任意一个网格物体 |
| VB / IB | 顶点数据 / 三角形索引数据 |
| Hash | 捕获资源身份，不是肉眼颜色，也不一定是文件校验值 |
| Slot / ps-tN | 某次着色器绘制用的贴图绑定位置 |
| draw / pass | 一次绘制 / 一个可能使用不同资源的渲染阶段 |
| STU | ShaderTextureUsage.json，捕获贴图绑定的证据 |
| Basis / ShapeKey | 基础形状 / 相对参考形状保存的变化 |
| 映射 | 名字或身份的对照字典，不是权重传递本身 |
| LOD | 特定精细度/距离使用的几何 |
| 旁车 sidecar | 和主源文件放在一起的生成辅助文件 |
| fail closed | 必要证据不明确就停止，不静默乱猜 |

##### 小案例
“该 Component 没有安全 Slot 证据”，意思是不能证明在该部件 draw 期间该把图绑在哪里，不等于 PNG 一定损坏。

##### 检查与排错
示例中的名字和数字仅供理解，真实 Component、骨骼、Slot、Hash 必须来自自己的工程。以后新增功能，按插件同一顶部 Tab 与面板位置找，不必从时间顺序更新日志里翻。
